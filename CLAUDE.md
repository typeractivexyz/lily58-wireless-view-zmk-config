## Project Overview

ZMK firmware config for **Krish's Typeractive Lily58 wireless split keyboard**. Forked from Nick Winans' Lily58 config (which descends from `unified-zmk-config-template`). There is no local toolchain requirement — firmware is built by GitHub Actions on every push.

## The Physical Keyboard (source of truth — do not re-ask)

| Part | Detail |
|---|---|
| PCB | Typeractive Lily58 wireless (partially assembled: hotswap sockets, diodes, battery jack, power switch, reset pre-soldered) |
| Controllers | 2× **nice!nano v2** (nRF52840, 1MB flash/256KB RAM, UF2 bootloader, charges at 100 mA default) |
| Displays | 2× **nice!view** (Sharp LS011B7DH03 memory-in-pixel LCD, 160×68, ~10 µA panel draw) — native support on Typeractive PCB, no CS bodge wire needed |
| Switches | 60× **Kailh Choc Sunset** tactile (Choc v1/PG1350, 40 gf actuation, 55 gf bump, 1.5 mm pre-travel / 3.0 mm total, factory-lubed) — bought from KEEBD |
| Keycaps | Blank Choc v1 caps, all white (two-prong stem; MX caps never fit): 8× convex 1u (thumbs), 2× homing 1u (F/J), 2× 1.5u, rest standard 1u |
| Batteries | 2× **1800 mAh LIP1359** PS3-controller replacement cells (3.7 V LiPo). Label likely overstated — real capacity ~700–1300 mAh typical for these. See battery safety below |
| Case | **Custom CAD-modeled case**, white print, faceplate + bottom shell, fixed **3.25° typing angle** |
| Central half | **Left** (plug USB into left) |

### 🔴 Battery safety (LIP1359 packs)

- **Polarity is NOT standardized**: game-controller packs and the maker/JST convention are opposite ~half the time. Reversed polarity can destroy the nice!nano and is a LiPo fire risk. Any battery work: verify red/+ lands on B+ with a multimeter first, per pack — never assume both packs match.
- nice!nano v2 has **no low-voltage cutoff** — the pack's own protection circuit (PCM) is the only over-discharge guard. Cheap replacements sometimes omit it.
- Keep charging at the **default 100 mA** (LIP1359 spec max is 0.4 A; do not bridge the 500 mA jumper). Full charge ≈ 13–18 h.
- Expected life — Krish's ZMK power profiler run (1800 mAh, split, nice!view, 2 BLE profiles, 30% asleep): **central 3 mo 4 wks (±4 wks), peripheral 1 yr 3 d (±3 mo)**. Real capacity likely lower than label, scale down accordingly.

## Repo Architecture

Eight files do everything:

- `build.yaml` — build matrix, all `nice_nano_v2`: `lily58_left nice_view_adapter nice_epaper`, `lily58_right nice_view_adapter nice_epaper`, and `settings_reset` (pairing-recovery firmware). `nice_epaper` is the **zmk-nice-oled module's** nice!view shield, a drop-in for stock `nice_view` (both `requires: [nice_view_header]`); shield order matters: `nice_view_adapter` must precede it.
- `config/west.yml` — pins ZMK to the **`v0.3`** tag, plus the **`zmk-nice-oled`** module pinned to sha `46f824ab...` (never a branch). ⚠️ That module is ZMK-v0.3-only and unmaintained since 2026-01-26 — it is the thing that blocks a future v0.4 bump (upstream issue #22). Dossier: `docs/zmk-nice-oled.md`.
- `.github/workflows/build.yml` — delegates to the reusable workflow `zmkfirmware/zmk/.github/workflows/build-user-config.yml@v0.3`. Push trigger uses a `paths` ALLOWLIST (`config/**`, `build.yaml`, the workflow itself) — docs, README, and keymap-drawer bot commits never build or release.
  - ⚠️ **PATHS ALLOWLIST RULE (from Krish):** whenever a new firmware-affecting file or folder is added to this repo — a custom shield/widget module, `boards/**`, a new snippet, extra `.conf`/`.dtsi`/`.keymap` outside `config/`, anything the compiled uf2 depends on — you MUST add its path to the `paths:` list in build.yml in the same commit, or firmware silently stops rebuilding for it. Files that only affect docs/diagrams stay OFF the list. A second `release` job (main-branch pushes + manual runs only) downloads the `firmware` artifact, renames the uf2s to friendly names (`lily58_left.uf2` etc.), and publishes a GitHub Release via `softprops/action-gh-release@v3` (download via `actions/download-artifact@v8`) — tag `vYYYY.MM.DD-<shortsha>`, title = timestamp only in NZ time (`TZ='Pacific/Auckland'`, auto NZST/NZDT), minimal body (commit link + flash one-liner + recovery note — no Built/stack lines, no table, per Krish). Releases attach left/right only; `settings_reset.uf2` stays artifact-only (Krish's call).
  - ⚠️ **The ZMK version is pinned in TWO places** (west.yml `revision:` and the workflow `@ref`). Always bump both together.
- `.github/workflows/draw-keymaps.yml` — keymap-drawer CI via `caksoylar/keymap-drawer/.github/workflows/draw-zmk.yml@main`; on keymap pushes it renders `keymap-drawer/lily58.svg` (+ `.yaml`) and commits them back (README embeds the SVG). Styling lives in `keymap-drawer/config.yaml` — moved out of the repo root 2026-07-30, so `config_path:` in the workflow is now load-bearing (see gotcha below).
- `config/lily58.conf` — Kconfig: **deep sleep OFF** (Krish, 2026-07-30), BT TX +8 dBm, eager debounce (press 1 ms / release 7 ms), low-latency BLE conn params, the three display lines (`ZMK_DISPLAY`, `ZMK_DISPLAY_STATUS_SCREEN_CUSTOM`, `NICE_EPAPER_ON=y` + `NICE_OLED_ON=n`), split peripheral battery fetching + proxy, USB logging off, rotary encoder (`CONFIG_EC11` + `CONFIG_EC11_TRIGGER_GLOBAL_THREAD`). ⚠️ `NICE_EPAPER_ON` is load-bearing — it selects every nice!view-flavoured default (68×160 portrait canvas, VDB 100, DPI 161, all widget coordinates). Wrong value = widgets render off-screen.
- `config/lily58_left.conf` — **central-half-only** Kconfig, merged on top of `lily58.conf` for the left build. Holds `CONFIG_BT_MAX_PAIRED=4` + `CONFIG_BT_MAX_CONN=4` = **3 BLE host profiles** (Krish's max, 2026-07-30), `CONFIG_ZMK_SPLIT_BLE_PREF_LATENCY=0` (the split-link half of the latency fix, 2026-08-10), plus all the **central screen widgets** (modifier indicators, WPM speedometer, CapsLock, layer). Those widget symbols only EXIST on a central build — the module wraps them in `if !ZMK_SPLIT || ZMK_SPLIT_ROLE_CENTRAL` — so putting them in the shared conf would warn about undefined symbols on the right half.
- `config/lily58_right.conf` — **peripheral-half-only** Kconfig (added 2026-08-07). Picks the right screen's animation. ⚠️ Read its comments before changing: the module resolves animations through an `#elif` chain (HEAD > CAT > SPACEMAN > POKEMON > gem-fallback) with CAT defaulting to `y`, so any other choice needs the higher-priority ones set to `n`.
- `config/lily58.keymap` — **stock upstream Typeractive layout as of 2026-08-13** (Krish: his customised version had become "annoying to use"). No combos — but Krish has since edited it in the web Keymap Editor, so it is no longer verbatim upstream (see below). **Homerow mods were re-added 2026-08-13** (his ask, after a research pass): a `behaviors {}` block with `hml`/`hmr` per urob's timeless recipe on `A S D F` = ⌃⇧⌥⌘ and `J K L ;` = ⌘⌥⇧⌃ (positions 25-28 / 31-34) — full spec and the reasoning in **`docs/timeless-homerow-mods.md`**. 3 layers (Base / Lower / Raise): Base = ESC-row numbers with GRAVE at the right pinky, Ctrl/Shift on the pinkies, `mo 1` / `mo 2` on the thumbs plus **two `&mt` mod-taps on the left thumbs — `&mt LALT UP` (pos 50) and `&mt LGUI DOWN` (pos 51)**, i.e. tap = arrow, hold = ⌥/⌘; Lower = **only** vim arrows (H/J/K/L → ←↓↑→, positions 30-33), everything else `&trans`; Raise = `&bt BT_SEL 0/1/2` at positions 1-3 + `&bt BT_CLR` at position 5, the shifted-number symbol block on the right hand, everything else `&trans`. ⚠️ Both layers were swapped relative to upstream and then stripped down (Krish, 2026-08-13) — the `mo 1` / `mo 2` thumb keys, the layer node names, and the `display-name`s were deliberately left alone. No F-keys, no numbers, and no left-hand symbols anywhere any more. **ZMK Studio is removed for good (Krish, 2026-08-10), so upstream's three `status = "reserved"` `extra_N` layers are deliberately NOT carried over — do not re-add them, nor any `CONFIG_ZMK_STUDIO*`.** **Rotary encoder** (EC12, no push button) on the LEFT half — **per-layer: Base = `PAGE_UP`/`PAGE_DOWN`, Lower = brightness ±, Raise = volume ±**. Hardware-verified 2026-07-23. Position 42 (row 4, 7th key — the left inner-bottom dead slot the encoder physically replaced, upstream's `[`) holds the matching marker keycode per layer (`SCROLLLOCK` / `C_BRIGHTNESS_AUTO` / `K_MUTE`) purely so keymap-drawer can draw the knob — see the drawer note below. The previous custom keymap is kept locally as `config/lily58.keymap.backup` (gitignored via `*.backup`). Do NOT re-add homerow mods, combos, or re-map anything uninvited.

## Git Workflow Rule (from Krish, 2026-07-16)

**Never `git push` without asking.** Commit locally as work progresses; when a chunk is done, ask Krish whether to push. Every push burns a CI firmware build and (on main) publishes a GitHub Release — he controls the trigger.

### ⚠️ POST-PUSH RULE (from Krish, 2026-07-30) — mandatory, every single push

After any push that builds firmware: **watch the run, then download all three uf2s into `firmware/` and rename them to `left.uf2`, `right.uf2`, `reset.uf2`.** Not optional, not "if asked" — it's part of finishing a push. Krish flashes from this folder, so stale or oddly-named files there are worse than none.

```bash
gh run watch <run-id> --exit-status               # wait for green first
rm -rf firmware && gh run download <run-id> -n firmware -D firmware
cd firmware
mv "lily58_left nice_view_adapter nice_view-nice_nano_v2-zmk.uf2"  left.uf2
mv "lily58_right nice_view_adapter nice_view-nice_nano_v2-zmk.uf2" right.uf2
mv "settings_reset-nice_nano_v2-zmk.uf2"                           reset.uf2
```

Notes: `firmware/` is in `.gitignore` — these stay local, never commit them. `rm -rf firmware` first so a failed/partial download can't leave last build's uf2s sitting there looking current. Artifact names embed the full shield string, so they change if `build.yaml`'s shields change — match on the `lily58_left` / `lily58_right` / `settings_reset` prefix rather than trusting the literal names above. Three files must land; if the artifact has fewer, a build target failed — say so instead of shipping a partial set.

## Common Commands

No local build needed — push and let CI build:

```bash
git push                                  # triggers firmware build
gh run watch                              # watch the build
gh run download -n firmware -D firmware/  # grab latest .uf2 artifacts (then rename — see post-push rule)
```

Flash: plug half in over USB-C → double-tap reset → mounts as UF2 mass-storage drive → drag the matching `.uf2` (left firmware to left half, right to right). Flash **both** halves whenever split-communication-relevant things change; keymap-only changes generally need only the central (left).

Optional local build (rarely needed):

```bash
west init -l config && west update && west zephyr-export
west build -s zmk/app -b nice_nano_v2 -- -DZMK_CONFIG=$PWD/config -DSHIELD="lily58_left nice_view_adapter nice_view"
```

Keymap diagram (runs automatically in CI on keymap pushes; local render if wanted):

```bash
# needs Python >=3.10 (system python3 is 3.9): uv venv --python 3.12 (uv at ~/.local/bin/uv)
pip install keymap-drawer
# -c goes BEFORE the subcommand (inside `parse`, -c means --columns!); CI auto-detects the config
keymap -c keymap-drawer/config.yaml parse -z config/lily58.keymap > keymap-drawer/lily58.yaml
keymap -c keymap-drawer/config.yaml draw keymap-drawer/lily58.yaml > keymap-drawer/lily58.svg
```

## Key Facts & Gotchas

- **ZMK v0.3.0 is the latest stable** (verified 2026-07-16; no v0.4 tag yet — claims of "v0.4.1" refer to the separate zmk-cli repo). v0.4 will move to Zephyr 4.1 + HWMv2; nothing in it we need yet.
- The v0.3 pin avoids ZMK issue #2990 (nice!nano v2 power regression on `main` from `SOC_DCDC_NRF52X_HV`). Don't switch back to `revision: main` casually.
- **ZMK Studio is gone and stays gone** (Krish, 2026-08-10 — "I never want to ever use it"). No `CONFIG_ZMK_STUDIO`/`_LOCKING`, no `studio-rpc-usb-uart` snippet, no reserved layer slots. Keymap changes are edit-and-reflash only.
- **Display needs `CONFIG_ZMK_DISPLAY=y` in `.conf`** — verified against the v0.3.0 tree: nothing in `nice_view`/`nice_view_adapter`'s Kconfig selects or implies it, so upstream Typeractive's config (which omits it) builds with blank screens. Still true with `nice_epaper`, which additionally wants `ZMK_DISPLAY_STATUS_SCREEN_CUSTOM=y` and the `NICE_EPAPER_ON` / `NICE_OLED_ON` pair.
- **Battery reporting is already on** — `ZMK_BLE` does `imply ZMK_BATTERY_REPORTING`, and the nice!nano v2 dts declares `zmk,battery = &vbatt`. Each half's widget only ever shows its OWN level; `ZMK_SPLIT_BLE_CENTRAL_BATTERY_LEVEL_FETCHING` + `_PROXY` are what get the right half's level to the host.
- **Typing arriving in chunks = BLE conn params, not debounce.** ZMK v0.3 defaults `BT_PERIPHERAL_PREF_LATENCY=30` at a 7.5–15 ms interval, i.e. the keyboard may ignore the host for ~450 ms and the host then flushes a burst. Fix in `.conf`: `BT_PERIPHERAL_PREF_MIN_INT=6` / `MAX_INT=6` / `LATENCY=0`. Costs central battery. **The split link has the SAME bug and needed the same fix** — `ZMK_SPLIT_BLE_PREF_LATENCY` also defaults to 30 (at `ZMK_SPLIT_BLE_PREF_INT=6`), set to 0 in `lily58_left.conf` on 2026-08-10. If chunking somehow persists after both, the remaining suspect is the display repainting every keystroke (see the 2026-08-10 log entry). `ZMK_BLE_EXPERIMENTAL_CONN` is NOT a latency fix — in v0.3 all it does is turn off `BT_CTLR_PHY_2M`.
- Halves lost pairing? Flash `settings_reset.uf2` (built in every CI artifact) to BOTH halves, then re-flash normal left/right firmware.
- ⚠️ **The drawer config is NOT auto-detected any more.** keymap-drawer only auto-finds `keymap_drawer.config.yaml` at the **repo root**; since 2026-07-30 it lives at `keymap-drawer/config.yaml`, so `-c keymap-drawer/config.yaml` (local) and `config_path:` (CI) are mandatory. Omitting them does NOT error — it silently renders with library defaults, losing every custom legend and the encoder knob. Also keep `keymap-drawer/config.yaml` in the `paths:` trigger of draw-keymaps.yml, or styling-only edits stop re-rendering.
- keymap-drawer's bot commit lands on `main` after each keymap push — `git pull` before local work to avoid diverging.
- **Rotary encoder — LEFT half only** (EC12, no push button; hardware-verified 2026-07-23). Stock ZMK v0.3 lily58 shield already defines `left_encoder` (`compatible = "alps,ec11"` — that's ZMK's driver name, drives EC11/EC12 alike; `pro_micro 21`=A / `20`=B, steps 80) + `sensors` node (`triggers-per-rotation=20`, lists only left), and `lily58_left.overlay` sets it `okay` — so enabling it needs NO overlay/node redefinition: just `CONFIG_EC11=y` + `CONFIG_EC11_TRIGGER_GLOBAL_THREAD=y` in `.conf` and one `sensor-bindings` line per keymap layer. `pro_micro` is the ZMK connector nodelabel (a shim — it stays in devicetree even though the board is a nice!nano v2, NOT a Pro Micro); on the nice!nano v2 those logical pins are the pads carrying **P0.31** (`pro_micro 21` = A) and **P0.29** (`pro_micro 20` = B), common leg to `GND`. Encoder works ONLY on the left; right half never has one. Wrong direction? swap the two keycodes. Wiring in memory (`rotary-encoder-future-add`) and the wiring artifact.
- ⚠️ **The 68-pixel rule.** The module draws on a PORTRAIT canvas `CONFIG_NICE_OLED_CUSTOM_CANVAS_WIDTH = 68` px wide and software-rotates it 90° onto the 160×68 panel (`widgets/util.c: rotate_canvas`). **Any pre-rotation X ≥ 68 is off the screen.** Several of the module's own `nice_epaper` X defaults violate this — modifiers 62 (a 30 px-wide box → right column at 78-92 gone), HID indicators 100, Luna 100, `PROFILE_BIG` 18 + 5×14 px = 88. That's upstream issue #26 ("modifiers sent all the way off the screen, only a sliver visible"). **Set every X explicitly and check it against 68**; never trust a module position default. Y has 160 to play with and is much safer.
- nice!view display = **zmk-nice-oled's `nice_epaper` shield** (adopted 2026-08-07, Krish's ask — he disliked the stock widget). Full dossier in **`docs/zmk-nice-oled.md`**; read it before changing any `NICE_OLED_*` flag. Six traps that are already worked around in the confs and must stay that way: (0) the 68-pixel rule above; (0b) **`HID_INDICATORS=y` renders nothing** unless Luna or Bongo Cat is attached — `hid_indicators.c` defines `HID_HAS_ANIMATION` only under those two and its `#else` does an unconditional `lv_label_set_text(label, "")`, so it costs RAM for a blank; and (1) **modifier indicators and Luna/Bongo Cat cannot coexist** on nice_epaper — Luna freezes while typing (upstream issue #30), we chose modifiers; (2) `RESPONSIVE_BONGO_CAT=y` **cannot link** (asset file commented out of the module's CMakeLists, symbols undefined — my finding, unreported upstream); (3) `SMART_BATTERY=y` `#if`-outs every animation (issue #31) and the author advises against it; (4) `..._ANIMATION_PERIPHERAL_GEM=y` is a **no-op** — gem is only the `#else` fallback. `docs/zmk-nice-oled.md` is the only display doc — the older `docs/displays.md` was deleted 2026-08-13 as redundant.
- Blank Choc caps fit fine; on choc-spaced PCBs the caps sit nearly gapless, on MX-spaced they'd show gaps — cosmetic only.

## Learnings Log

- **2026-08-13** — **Homerow mods re-added, this time as stock urob** (Krish's ask after a research pass; full dossier in **`docs/timeless-homerow-mods.md`**). Two behaviors only — `hml`/`hmr`, identical apart from the positional list — `balanced`, tapping-term **280**, quick-tap **225** (his call; urob 175, linkarzu 300), require-prior-idle **150**, `hold-trigger-on-release`, `hold-trigger-key-positions = <KEYS_R THUMBS>` / `<KEYS_L THUMBS>`. Mods are **⌃⇧⌥⌘ on A S D F, mirrored** (⌘ on the index — deliberately the REVERSE of both urob and linkarzu, who put ⌘ on the pinky; Krish's call, and defensible on macOS where ⌘ is the most-used mod). Key facts learned: (1) **hold-tap needs ZERO Kconfig** — verified urob's own three `.conf` files carry nothing HRM-related, and v0.3.0's only knobs are `ZMK_BEHAVIOR_HOLD_TAP_MAX_HELD` (default 10) / `_MAX_CAPTURED_EVENTS` (default 40), both far above 8 HRMs. (2) ⚠️ **`require-prior-idle-ms` is a single GLOBAL timer**, not per-key (`behavior_hold_tap.c:130`), and **modifiers do not reset it** (line 792 `!is_mod(...)`); layer keys don't either (there's a `// we want to catch layer-up events too... how?` comment at line 789). (3) **`quick-tap-ms` only ever applies to the same physical key** — line 148 requires `last_tapped.position == hold_tap->position`, and that position is only recorded by a hold-tap resolving as a tap, so a plain `&kp` can never match it. (4) `hold-while-undecided` + `_linger` **do exist in v0.3.0** and are the documented fix for modifier-with-mouse (⌘-click, drag-select) — not enabled, but noted. (5) **Position 42 is excluded from `KEYS_L`** — it's the encoder's dead slot, no switch fitted. (6) The drawer needed **no config change**: it parses the hold-taps itself and `zmk_keycode_map` already renders ⌃⇧⌥⌘. Deliberately left alone: the `&mt LALT UP` / `&mt LGUI DOWN` thumbs (Krish's call — one change at a time; they stay `hold-preferred`/200 ms, so ⌥ and ⌘ now exist in two places). His `&kp RSHFT` at pos 49 satisfies urob's one hard requirement, a dedicated shift. NOT flash-tested; keymap-only, so the left/central half is enough. ⚠️ **Supersedes the old "don't re-add homerow mods" rule** — he asked for these; don't re-tune the numbers or the mod order uninvited.
- **2026-08-13** — **Research: linkarzu's Toucan vs urob, and why their numbers differ** (`docs/timeless-homerow-mods.md`). Both agree on `balanced` + `hold-trigger-on-release` + `require-prior-idle-ms = 150`; they differ on tapping-term (280 vs 300, which barely matters — in this design the term only governs bare-modifier presses and same-hand mod+alpha) and on quick-tap (175 vs 300). The quick-tap gap is NOT a tuning decision: linkarzu's git history shows his pre-urob config already ran 300/300 back on 2025-12-31, and he simply keeps quick-tap locked equal to the tapping term (200/200 → 250/250 → 300/300). ⚠️ **GitHub's API omits `patch` for large diffs**, so a few of his commits can't be traced this way — don't claim a full history from `gh api` alone. The genuinely valuable find is his tuning arc on `require-prior-idle-ms`: **125 → 75** ("for shift in homerowmods") → **125 + a physical `&kp LSHFT` thumb key** ("reddit was right") → **150**. I.e. he hit exactly the shift false-negative urob warns about, failed to fix it by tuning, and fixed it structurally with a dedicated shift. Lesson for future HRM complaints here: **don't touch the numbers for shift problems — check the dedicated shift key first.** Also: urob's readme "Bonus: faster GitHub Actions workflow" is a **Nix-based replacement** for the whole upstream reusable workflow; not worth adopting here (our builds are ~3 min and delegate to `build-user-config.yml@v0.3`).
- **2026-08-13** — **The two `&mt` thumb keys now render as modifier keys** (Krish asked for blue, then for it to be 1:1 identical to the other modifier keys — so it ended up as the existing `.mod` styling, no new CSS). Drawer-only: `raw_binding_map` entries for `&mt LALT UP` / `&mt LGUI DOWN` with `type: "mod"`, which produces byte-identical classes to a standalone mod key (`class="key mod"` on the rect, `key mod tap` / `key mod hold` on the legends — verified against `&kp RSHFT` at keypos-49). ⚠️ **keymap-drawer has NO built-in `.mod` type** — checked `config.py`'s default CSS: only `.held`, `.ghost`, `.combo`, `.trans` etc. exist, and `type:` is just "whatever string you pass becomes a CSS class".
